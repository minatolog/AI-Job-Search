## 13. Schedule Adjustment Rules for Codex

These rules are mandatory.

### Rule 1 — Never rewrite completed history

If a day is completed, do not retroactively modify what was originally planned or what the user actually did.

Preserve:
- Planned task
- Actual completion
- Completion percentage
- Problems

Only future tasks can be rescheduled.

### Rule 2 — Carry unfinished prerequisites forward

Example:

If Day 3 Embedding is completed but Cosine Similarity is unfinished:

- Do not mark Day 3 as fully complete.
- Add Cosine Similarity to the next available day.
- Check whether future Vector Search tasks depend on it.
- Adjust future workload accordingly.

### Rule 3 — Protect critical learning order

Priority order:

```text
RAG fundamentals
>
Tool Calling
>
Agent
>
LangGraph
>
FastAPI
>
SQL integration
>
MCP
>
Optional frameworks
```

Do not skip a prerequisite simply to preserve the original calendar.

### Rule 4 — Do not endlessly delay job applications

Even if the user falls behind in learning:

- Continue suitable applications.
- Use B/C tier interviews and tests as practice.
- Do not tell the user to stop all applications until learning is complete.

### Rule 5 — Adjust scope before extending the entire schedule

When overloaded:

1. Remove low-priority optional content.
2. Reduce framework breadth.
3. Simplify project features.
4. Preserve core RAG + Agent + LangGraph + FastAPI path.
5. Only extend deadlines if necessary.

### Rule 6 — Account for COMP9900 and university workload

If COMP9900 or coursework unexpectedly consumes substantial time:

- Reduce that day's optional study load.
- Preserve at least one small coding or review task whenever realistic.
- Move large tasks to weekends when possible.

### Rule 7 — Use real recruitment feedback to reprioritize

Whenever the user completes a written test or interview:

- Record all remembered questions.
- Tag each question by category.
- Identify whether the issue was:
  - Never learned
  - Learned but forgotten
  - Understood but could not explain
  - Coding weakness
  - Time pressure
- Increase study priority for recurring gaps.

### Rule 8 — Avoid fake progress

Do not mark a topic complete merely because the user watched a tutorial.

A technical topic is "Done" only when the user can do at least one of:

- Implement it
- Explain it clearly
- Answer interview questions about it
- Demonstrate it in the project

### Rule 9 — Maintain a weekly review

At the end of each 7-day period, generate:

- Planned completion rate
- Actual completion rate
- Main blockers
- New skill gaps
- Applications sent
- Tests completed
- Interviews completed
- Project milestone reached
- Changes for the next week
